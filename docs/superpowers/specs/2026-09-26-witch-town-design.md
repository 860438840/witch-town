# 女巫镇（Salem 1692）微信小程序 — 设计文档

- 日期：2026-09-26
- 状态：待用户审阅

## 1. 目标与范围

把桌游《女巫镇 / Salem 1692》（简体中文版，15 个有技能的角色）做成微信小程序，供自己和朋友在线联机游玩。

**已确定的前提**

| 项目 | 决定 |
|---|---|
| 玩法 | 纯线上联机，每人用自己的手机，4–12 人 |
| 交流 | 小程序内不做聊天/语音；大家另开微信群语音。小程序提供事件日志 |
| 发布 | 只用开发版/体验版邀请朋友，不正式发布，不考虑版号、审核、运营 |
| 后端 | 微信云开发，使用免费云环境（未发布阶段免费，额度 20 万次调用/月） |
| 规则来源 | andyventure.com 网页规则 + 用户实体卡（简体版）照片；缺失细节以官方 Salem 1692 补齐，并经用户确认 |
| 语言 | 界面全部简体中文 |

**第一版不做**：动画特效、音效、战绩统计、断线换人接管、实体卡原画（版权原因，用纯色卡面+文字+图标）。

**成功标准**：4–12 名朋友能在各自手机上完整玩完一局，规则（含 15 个角色和下文全部裁定）由服务器正确执行，任何玩家都无法从客户端获取他人的隐藏信息。

## 2. 游戏规则（权威版本）

### 2.1 身份卡

- 种类：**女巫**、**警长**、**村民**（不是女巫）。
- 4–12 人**一律每人 5 张**，背面朝上排成一排，只有本人知道内容。
- 数量：

| 人数 | 女巫 | 警长 | 村民 | 总数 |
|---|---|---|---|---|
| 4 | 1 | 1 | 18 | 20 |
| 5 | 1 | 1 | 23 | 25 |
| 6–12 | 2 | 1 | 人数×5−3 | 人数×5 |

- **女巫阵营**：开局持有女巫卡的玩家属于女巫阵营；之后通过「传染」拿到女巫卡的玩家也加入女巫阵营。**阵营是永久的**：女巫卡被人拿走，原持有者仍是女巫阵营。
- **警长**：当前持有（未翻开的）警长卡的玩家就是警长。警长卡被传染拿走，则拿到的人成为新警长。**警长卡一旦被翻开，本局不再有警长能力。**警长也可能同时是女巫阵营。
- 身份卡被翻开后正面朝上，所有人可见。
  - 翻开的是**女巫卡** → 该玩家立即死亡。
  - 玩家的 5 张身份卡**全部翻开** → 该玩家立即死亡。

### 2.2 游戏卡（共 60 张，数量做成常量便于调整）

**红卡（指控）**：放在目标玩家面前，按点数累计。

| 卡 | 数量 | 点数 |
|---|---|---|
| 指控 | 35 | 1 |
| 证据 | 6 | 3 |
| 目击 | 1 | 7 |

**蓝卡（装备）**：放在目标玩家面前，持续生效，直到被移除。

| 卡 | 数量 | 效果 |
|---|---|---|
| 黑猫 | 1 | 不进牌堆，由女巫在第一夜放置。「传染」打出时，持有者先翻开自己一张未翻开的身份卡 |
| 情侣 | 2 | 两张分别放在两名玩家面前，两人成为情侣：其中一人死亡，另一人同时死亡 |
| 避难 | 1 | 持有者在夜晚不会被女巫杀死 |
| 信徒 | 1 | 其他玩家不能对持有者打出红卡 |

**绿卡（一次性）**：结算后进入弃牌堆。

| 卡 | 数量 | 效果 |
|---|---|---|
| 嫁祸 | 2 | 选择一名玩家，将其面前所有蓝卡、绿卡、红卡转移给另一名玩家 |
| 抢劫 | 1 | 选择一名玩家，将其所有手牌交给另一名玩家 |
| 纵火 | 1 | 选择一名玩家，丢弃其所有手牌 |
| 诅咒 | 1 | 选择一名玩家，丢弃其面前一张蓝卡 |
| 拘留 | 3 | 目标玩家跳过其下一回合 |
| 辩护 | 3 | 选择一名玩家，丢弃其面前最多 3 张「指控」或 1 张「证据」 |

**黑卡（事件）**：抽到时立即打出结算。

| 卡 | 数量 | 效果 |
|---|---|---|
| 传染 | 1 | 见 2.5 |
| 夜晚 | 1 | 见 2.6 |

**出牌对象**：红卡不能打给自己；蓝卡、绿卡可以打给任何活着的玩家（包括自己）。

### 2.3 审判

- 每名玩家面前的红卡点数累计。累计点数**达到或超过审判线**时立即审判。审判线默认 **7**（大力士为 **8**；法官出牌时为 **6**，见角色）。
- 打出使点数越线那张红卡的玩家是**审判发起者**。
- **被审判者自己选择**翻开一张未翻开的身份卡（超时则随机）。
- 审判结束后，丢弃被审判者面前的**所有红卡**。

### 2.4 开局

1. 发角色：人数 < 7 时每人从随机 2 张角色中选 1 张；≥ 7 时直接随机发。角色公开。
2. 发身份卡（见 2.1）。
3. 从游戏卡中取出黑猫、夜晚、传染；其余洗匀，每人发 3 张手牌。
4. 把**夜晚和传染一起洗进剩余牌堆，位置随机**。
5. **第一夜（黑猫之夜，不杀人）**：女巫阵营互相确认同伴，共同选择一名玩家（可以是女巫自己）放置黑猫。
6. 由黑猫持有者开始白天回合。

### 2.5 白天回合

- 按座位**顺时针**轮流。座位列表按顺时针排列：**左边邻居 = 下一个座位，右边邻居 = 上一个座位**。
- 轮到的玩家二选一：
  - **抽 2 张牌**（抽到黑卡立即结算，然后继续抽满 2 张）；或
  - **打出任意张**红/蓝/绿卡。
- 手牌无上限。
- 被「拘留」的玩家跳过其下一回合，然后移除拘留状态。
- 牌堆抽空时（理论上不会发生，因为夜晚在牌堆内），把弃牌堆洗成新牌堆。

**传染**
1. 黑猫持有者翻开自己一张未翻开的身份卡（由他选择）。
2. 所有活着的玩家**同时**从左边邻居（第一个活着的左侧玩家）的**未翻开**身份卡中盲选一张拿走（超时随机）。
3. 拿到女巫卡 → 加入女巫阵营（仅本人收到提示，女巫同伴列表更新）。拿到警长卡 → 成为警长。
4. 传染卡进入弃牌堆。

### 2.6 夜晚

1. 所有玩家同时操作（界面结构相同，防止泄露身份）：
   - 活着的女巫阵营：选择击杀目标。多名女巫能实时看到同伴的选择，**必须一致才能确认**。
   - 警长（若存在且警长卡未翻开）：选择保护一名玩家，**不能保护自己**。
   - 其他玩家：选择「怀疑对象」（纯装饰，无效果）。
   - **所有玩家**最后一步：是否**自首**。自首 = 自选翻开一张身份卡，本夜免疫击杀。
2. 结算：击杀目标若**没有**警长保护、**没有**避难、**没有**自首 → 死亡。
3. 把**弃牌堆 + 剩余牌堆 + 夜晚卡**洗成新牌堆（传染也会因此回到牌堆，一局可能多次传染）。
4. 由抽到夜晚的玩家的下一位继续白天回合。

### 2.7 死亡

- 死亡原因：夜晚被杀；翻出女巫卡；身份卡全部翻开；情侣连带。
- 死亡玩家的所有身份卡翻开公示；其手牌、面前的蓝卡和红卡进入弃牌堆（农民技能例外）。
- 死亡玩家不能再行动，回合跳过。

### 2.8 胜负

每次有身份卡翻开或有人死亡后检查：
- **村民胜利**：所有女巫卡都已翻开。
- **女巫胜利**：所有活着的玩家都是女巫阵营。
- 两者同时满足时，判村民胜利。

游戏结束后公开所有人的身份与阵营。

### 2.9 角色（15 个，均有技能，公开）

| 角色 | 技能 | 触发时机 |
|---|---|---|
| 医生 | 可以把「辩护」当作「目击」（7 点）打出 | 出牌 |
| 乞丐 | 对你打出的「抢劫」「纵火」无效，并立刻丢弃 | 被指定为目标 |
| 地主 | 抽牌时如果抽出 2 张「指控」（不含证据、目击），展示这 2 张，再抽一张 | 抽牌后 |
| 法官 | 你打出的红卡使目标累计达到 6 点，即可审判该玩家 | 出红卡 |
| 牧师 | 游戏中两次：抽牌时可改为从弃牌堆选最多 2 张非黑卡加入手牌 | 抽牌 |
| 说书人 | 游戏中一次：你的回合抽牌前，可任意调整当前牌堆顺序，限时 2 分钟 | 回合开始 |
| 裁缝 | 技能与右手边第一名活着的玩家一致 | 实时 |
| 家庭主妇 | 场上每有一张**其他玩家**的身份卡被翻开，你从牌堆抽一张牌；因死亡或自首导致的翻开不算 | 身份卡翻开后 |
| 农民 | 有玩家死亡时，你获得他的所有手牌和面前的蓝卡，全部放入手牌 | 他人死亡 |
| 小孩 | 你发起的审判结束后，立刻丢弃你自己面前所有「指控」和「证据」 | 审判后 |
| 部长 | 对你打出的「证据」只算 1 点 | 被出红卡 |
| 官员 | 游戏中一次：你自首时无需翻开身份卡 | 自首 |
| 大力士 | 对你的审判线为 8 点 | 审判判定 |
| 女仆 | 「黑猫」和「情侣」对你无效 | 被放置蓝卡 |
| 少女 | 你发起审判时，审判前先抽 2 张牌，可在本回合立即使用 | 审判前 |

### 2.10 规则裁定（已与用户确认）

1. **法官 vs 大力士**：法官对大力士出红卡时，以法官的 6 点为准。
2. **医生 vs 部长**：部长只削弱「证据」，医生当作目击的辩护仍算 7 点。
3. **女仆 + 情侣**：情侣对女仆无效，直接进入弃牌堆。
4. **女仆 + 黑猫**：第一夜女巫不能把黑猫放给女仆（界面禁选）；之后通过嫁祸转移给女仆的黑猫直接进入弃牌堆。
5. **裁缝**：实时复制右手边（上一个座位方向）第一名活着的玩家的技能；那人死亡则自动改为再下一位。次数限制类技能（说书人、牧师、官员）裁缝单独计算自己的次数。
6. **家庭主妇**：获得的牌从牌堆顶抽，抽到黑卡立即结算。
7. **身份卡**：4–12 人每人 5 张；4–5 人 1 女巫，6 人以上 2 女巫；警长 1 张。
8. **目击**：1 张，7 点。
9. **夜晚和传染**：开局都随机洗入牌堆；每次夜晚后与弃牌堆一起重洗。
10. **农民**：农民自己在同一事件中死亡（如情侣连带）时不获得卡牌。多人同时死亡时按座位顺序依次结算。

## 3. 架构

```
小程序（每人手机）  ──调用云函数 game──▶  云函数 game  ──▶  规则引擎 engine
  显示状态、发送操作  ◀──db.watch 推送──  云数据库（rooms / hands / games）
```

- **规则引擎 `engine/`**：纯 TypeScript，不依赖任何微信 API。核心接口：
  `apply(state, action, rng) → { state, events }`，非法操作抛出带原因的错误。
  - 随机数通过注入的 `rng` 提供，测试时可固定种子。
  - 角色技能以插件形式注册到固定**钩子**：`beforeDraw`、`afterDraw`、`onTargeted`、`accusationValue`、`trialThreshold`、`beforeTrial`、`afterTrial`、`onTryalRevealed`、`onDeath`、`onConfess`、`onBlueCardPlaced`。裁缝通过「查询右手边角色 → 调用其插件」实现。
  - `project(state, openid) → PrivateView` 和 `projectPublic(state) → PublicView` 负责生成视图。
- **云函数 `cloudfunctions/game`**：单一入口，按 `action` 分发：`createRoom`、`joinRoom`、`reorderSeats`、`startGame`、`act`（所有游戏内操作）、`tick`（超时推进）。每次写操作在事务中完成：读取 `games` → 校验版本号 → `engine.apply` → 写回 `games`、`rooms`、所有 `hands`。构建时把 `engine/` 编译产物复制进云函数目录。
- **小程序 `miniprogram/`**：原生小程序 + TypeScript，不使用 uni-app / Taro。

### 3.1 数据集合与权限

| 集合 | 内容 | 权限 |
|---|---|---|
| `games` | 完整局面（牌堆顺序、所有身份卡、夜晚选择、版本号、随机种子） | 客户端不可读写，仅云函数 |
| `rooms` | 公开视图：房号、房主、状态、座位（昵称、头像、角色、存活、已翻开身份卡、面前红卡点数与审判线、蓝卡、手牌数、未翻开身份卡数）、当前回合与阶段、倒计时截止时间、事件日志、牌堆/弃牌数 | 房间成员可读，客户端不可写 |
| `hands` | 私密视图（每人一条，`_id = roomId_openid`）：手牌、自己的身份卡、阵营、女巫同伴、当前待我做的选择 | 仅本人可读（`doc._openid == auth.openid`），客户端不可写 |

### 3.2 并发、超时与重连

- **并发**：`games` 带版本号；事务内校验，版本不一致时返回「状态已变化」，客户端自动刷新。
- **超时**：每个等待阶段在 `rooms` 中写入 `deadline`。任何在线客户端在倒计时结束后调用 `tick`，云函数确认已超时后执行默认操作：回合超时 → 抽 2 张；选择超时 → 随机合法选项。时长：回合 90 秒；审判/传染/夜晚选择 45 秒；说书人 120 秒。
- **重连**：客户端进入游戏页时读取 `rooms` 和自己的 `hands`，再建立 watch。
- **实时推送备用方案**：若免费环境不支持 `db.watch`，改为每 1.5 秒轮询 `rooms.version`，有变化时再拉取完整数据。

## 4. 界面

页面：**首页**（建房 / 输入 4 位房号）→ **房间大厅**（座位列表、房主可拖动调整座位、分享到微信群、开始）→ **游戏桌** → **结算页**（公开所有身份与阵营）。

**游戏桌布局（自上而下）**
1. 顶栏：牌堆数、弃牌数、当前回合玩家、倒计时。
2. 其他玩家：横向滑动的卡片，显示角色、红卡点数/审判线、蓝卡、手牌数、身份卡（已翻开显示内容）、死亡状态、黑猫标记。
3. 事件日志：显示最近几条，点击展开全部。
4. 我的状态：角色、红卡点数、我的身份卡（仅自己可见）。
5. 我的手牌 + 操作按钮「抽 2 张」「出牌」。

**交互**
- 出牌：点手牌 → 点目标玩家（双目标卡依次点两人）→ 确认。不做拖拽。
- 需要我做选择时（审判翻牌、传染盲选、说书人排序、牧师选牌、角色二选一、夜晚操作），从底部弹出面板并显示倒计时。
- 夜晚：全屏暗色，所有人面板结构相同（选择对象 → 是否自首）。
- 卡面：纯色（红/蓝/绿/黑）+ 卡名 + 效果文字 + 图标。

## 5. 测试

1. **引擎单元测试**（Vitest，Node 环境）：每张卡、每个角色、2.10 的每条裁定都有独立测试。
2. **随机对局模拟**：机器人随机执行合法操作，跑 1000 局，检查不变量：
   - 卡牌总数守恒（游戏卡 60 张、身份卡 = 人数×5）；
   - 每局在有限步内结束；
   - `projectPublic` 输出中永远不含未翻开的身份卡；`project` 输出中不含他人的手牌和未翻开身份卡。
3. **云函数测试**：用内存版数据库替身测试建房、加入、开局、出牌、版本冲突、超时。
4. **真机测试**：开发者工具多账号调试 + 2–3 台真机实际对局。

## 6. 开发顺序

| 步骤 | 内容 | 验收 |
|---|---|---|
| 0 | 在免费云环境中验证 `db.watch` 和数据库权限规则 | 确定推送还是轮询 |
| 1 | 引擎核心：开局、抽牌、红/蓝/绿卡、审判、死亡、胜负 | 测试中能打完无夜晚的一局 |
| 2 | 引擎：第一夜黑猫、夜晚、传染、自首、洗牌 | 全部基础规则测试通过 + 随机模拟通过 |
| 3 | 云函数 + 集合权限 + 首页/大厅 | 手机上能建房、加入、开局 |
| 4 | 游戏桌页面 | **第一个可玩版本**（角色暂无技能） |
| 5 | 角色：医生、乞丐、地主、部长、大力士、女仆、法官、小孩、官员 → 牧师、说书人、家庭主妇、农民、少女 → 裁缝 | 15 个角色测试通过 |
| 6 | 超时、重连、界面打磨 | 与朋友正式对局 |

## 7. 风险

- **免费环境的功能限制**：官方未列明具体限制；步骤 0 先验证。
- **云函数冷启动**：首次调用可能延迟 1–2 秒，回合制可以接受。
- **规则歧义**：实际游玩中发现的新歧义，记录到本文档 2.10 并补测试。

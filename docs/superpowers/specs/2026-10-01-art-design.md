# 美化 B：代码绘制的插画 — 设计

日期：2026-10-01
上级文档：`2026-09-26-witch-town-design.md`、`2026-09-28-plan-b2-minigame-ui-design.md`（界面）、`2026-10-01-plan-c-characters-design.md`（角色）
试验品：`assets/2026-10-01-art-prototype.html`（用户在手机上看过并确认「就按这版做」）
分支：计划 C 真机验收通过、分支合并之后，从合并结果开新分支 `feat/art`

## 1. 目标与范围

美化分三个子项目，按顺序做：**B 插画 → A 界面打磨 → C 动画特效**。本文只管 B。

1. 插画**全部用代码绘制**（Canvas 2D），不用任何图片文件。画风以试验品为准：剪影加木刻排线，深紫、暗金、暗红配色，颜色全部来自游戏现有调色板。
2. 画齐：15 种牌、3 种身份、卡背、15 个角色、4 幅场景（首页夜景、牌桌背景、村民胜利、女巫胜利）。
3. 把它们放进游戏里第 4 节列出的每个位置。

**不做**：面板、按钮、字体的整体打磨（子项目 A）；发牌、翻牌、夜雾等动画（子项目 C）；任何规则或服务器改动。

**成功标准**：手机上打开游戏，第 4 节列出的位置都换成了插画；小屏 320×568 不重叠；低端机牌桌不掉帧；小游戏包增加不超过 100KB。

## 2. 选型理由

| 方案 | 结论 |
|---|---|
| AI 生成图片 | 约 40 张、约 2MB，要用户出图；放弃 |
| 免费素材 | 风格难统一、缺对应题材；放弃 |
| **代码绘制** | 风格统一，体积约 60–80KB，改色、加牌只改代码，高分屏不糊。代价：只能画剪影和几何图形，画不出人物表情。用户看过试验品后接受 |

## 3. 结构

### 3.1 美术代码单独一处

在客户端主题目录下新建「美术」目录，分三部分：

- **图标**：每种牌、每种身份、每个角色一个绘制函数，统一的参数是「中心点 + 边长」。用按种类索引的完整表登记，漏画任何一种都会在类型检查时报错。
- **模板**：卡面（底色、金边、图框、牌名，红卡带点数）、卡背、身份卡面、角色卡（圆头像、名字绶带、技能说明、限次标记）、圆形头像。
- **场景**：首页夜景、牌桌背景、村民胜利、女巫胜利。星星位置等随机元素用固定种子，每次画出来一样。

现有的公共绘制函数（卡面、身份卡、头像、天空背景）**名字和参数不变**，内部改为调用美术代码；需要新信息时只加可选参数（例如头像加「角色」）。这样各界面的代码改动最小。

### 3.2 缓存

图标和场景笔画多（光晕、排线），牌桌每帧重画几十张会让低端机卡顿。规则：

- 每种图在每个尺寸下只画一次，画到一张隐藏画布上缓存，之后每帧直接贴图。
- 缓存键 = 图的种类 + 像素尺寸（含屏幕倍率）。尺寸变了就画一份新的。
- 带状态的效果（选中光晕、变暗、翻转动画的横向缩放）在贴图时处理，不进缓存键。
- 小游戏里用 `wx.createCanvas()` 建隐藏画布；测试里用假画布。

### 3.3 卡面不再放说明文字

现在的手牌上有 9 号字的说明，换成插画后去掉。点一下手牌，底部信息栏会显示说明（现有功能）。规则页每种牌、每个角色配小图标。

## 4. 每个位置的样子

身份卡在格子里只有 8×11 像素，放不下图标，所以分两种画法：

- **很小（宽度小于 16 像素）**：保持现有颜色区分（未翻开暗色、女巫红、警长金、村民灰）；未翻开的加细金边和中心小点，像缩小的卡背。
- **大一些**：完整卡背，以及女巫（尖帽和弯月）、警长（提灯）、村民（亮灯的小屋）的卡面。

| 位置 | 样子 |
|---|---|
| 手牌（58×84；小屏 44×64） | 新卡面。选中时金色光晕，不能打出的牌变暗，和现在一样 |
| 格子头像 | 有角色时圆里画角色图标，外圈用座位颜色；选角色之前保持首字彩色圆 |
| 格子里「面前的牌」 | 「黑情避」这类单字改成 10 像素小图标排成一排 |
| 我的信息栏头像 | 同格子 |
| 我的身份卡面板 | 完整卡面；未翻开的显示卡背加「未翻开」 |
| 传染时选身份卡、结算页的身份 | 按尺寸用上面两种画法之一 |
| 选角色面板 | 两张完整角色卡并排，选中的金光、上浮；下方「确认」 |
| 点格子看详情 | 顶部放此人的角色卡（缩小版），下面是现有文字 |
| 牧师从弃牌堆拿牌 | 网格里的文字格子改成小卡面 |
| 说书人调整牌堆 | 每行牌名前加小图标 |
| 弃牌堆列表 | 保持文字，每种牌前加小图标 |
| 首页 | 试验品里的小镇夜景（月亮、星空、小镇、教堂、绞刑架、雾），标题和按钮位置不变 |
| 大厅 | 同一幅夜景，压暗，房间列表要看得清 |
| 牌桌背景 | 保留星空，底部加压暗的小镇剪影；夜晚整体变暗、月亮更亮 |
| 结算页 | 村民胜利：黎明天色，太阳从小镇后升起；女巫胜利：血月，天空发红。玩家头像用角色图标 |
| 规则页 | 每种牌、每个角色的说明前加小图标 |

小屏 320×568 下所有位置不重叠、按钮在屏幕内。

## 6. 测试

- **类型检查**：每种牌、身份、角色在图标表里都有登记。
- **自动测试**（假画布）：每个图标、模板、场景都能在各种尺寸下画完不报错；缓存同种类同尺寸只画一次，换尺寸会重画；很小的身份卡走颜色画法、大的走卡面画法；各界面在 320×568 下不重叠（沿用现有布局测试）。
- **图鉴页**：用游戏真实的美术代码打包出一个网页，所有图一页看完，供用户在手机上检查。不进小游戏包。
- **真机**：上传体验版，在手机上看首页、大厅、牌桌（含夜晚）、各面板、结算页；牌桌操作不卡。

## 实现裁定与验收（2026-10-02）

### 与本文不同的地方

- §4「我的身份卡面板：未翻开的显示卡背」改为**全部显示卡面**：自己的身份卡自己本来就能看到，显示卡背反而丢信息；已翻开的仍标「·已翻开」。
- §4「格子里面前的牌：10 像素小图标」改为 **10×14 的迷你卡面**：单独的剪影在暗底上看不清，带底色的迷你卡能看清颜色。
- §4「点一下手牌，底部信息栏显示说明」原来只对不能打出的牌成立。选中可打出的牌后，信息栏改为「下一步做什么｜这张牌的作用」，例如「嫁祸」先选被拿走的人｜把一名玩家面前的所有卡转给另一名玩家。（最终审查发现。）
- 小屏渲染检查后调整：首页月亮挪到右边（原来压在标题后面）；女巫胜利页血月挪到右上角，标题改浅色（原来红字压红月）；结算页玩家行底色加深（黎明天色上字看不清）。
- 图鉴页除全部图标外，还把真实的界面场景画在 375×667 和 320×568 上，方便在浏览器里检查排版（`client/gallery/`，`npm run gallery`，不进小游戏包）。

### 最终审查修复（均有先失败的测试）

- 选角色面板滑入动画中每帧新建不同尺寸的隐藏画布：改为按停稳后的高度定卡片大小。
- 牧师面板在弃牌堆有 13 种非黑卡时确认按钮掉出屏幕：改为每行 5 张。
- 隐藏画布缓存加上限（小图最多 400 张，最久没用的先挤掉）；被挤掉的画布释放原生内存。

### 未处理的小问题

- 格子里面前超过两张牌时，多的不画，没有「+n」提示。
- 夜晚时牌桌月亮的光晕每帧新建一个渐变（开销很小）。
- 代码里有一处椭圆函数和一个配色重复。
- 牌桌月亮躲在右上角「牌堆 / 弃牌」数字后面（旧版本就这样，现在夜里更亮）。
- 审查者提出详情面板在小屏上可能放不下；用最长的情况试过没有复现，未改。

### 验收

- 小游戏包 172KB，比基线（115KB）增加 57KB，在设计目标（≤ 100KB）之内。
- 客户端 180 个测试通过；引擎、服务器未改动。
- 用户看过之后回复「大致没问题」，没有逐项列出检查结果。

# 女巫镇 · 计划 B2：小游戏界面设计

> 日期：2026-09-28。上位文档：`2026-09-26-witch-town-design.md`（规则 §2、架构 §3）。本文件取代上位文档 §4 的旧版（WXML）界面设计。

## 1. 目标与范围

**目标**：把临时调试界面换成真正能玩的小游戏界面，让 4–12 名朋友在各自手机上（体验版）完整打完一局。

**已确定的前提**

| 项目 | 决定 |
|---|---|
| 形态 | 微信小游戏，界面全部用 Canvas 2D 绘制，竖屏 |
| 视觉风格 | **月夜烛光**：深紫夜空渐变、弯月、烛光金色描边与高亮；卡面纯色渐变 + 金边 + 卡名 + 效果文字 |
| 装饰程度 | 静态美化 + 少量短动效（每个约 0.3 秒）；**不做音效** |
| 玩家摆放 | 游戏桌上所有玩家以**网格**排列（12 人为 4×3），一屏看全 |
| 邀请方式 | 大厅大字显示房号 +「复制房号」+「邀请」（发分享卡片）；首页「输入房号」放在最显眼处（见 §7.1） |
| 云端 | 使用计划 B1 已完成的云函数 `game` 和 `rooms` / `hands` 集合，**本计划不修改服务器接口** |
| 角色技能 | 不在本计划内（计划 C）。界面只显示角色名和技能说明文字（若状态中有角色） |
| 昵称与头像 | 微信已不向小游戏提供真实昵称和头像：首次进入时**自己输入昵称**（存本机）；头像用「名字首字 + 专属颜色」的圆形徽章 |

**不做**：音效、再来一局（结束后回首页重新建房）、聊天、战绩、踢人、实体卡原画。

**成功标准**：
1. 4–12 人在各自手机的体验版上，从建房、加入、开局一直玩到结算页，全程不需要调试界面。
2. 所有规则操作（抽牌、出牌、结束回合、审判翻牌、黑猫翻牌、传染盲选、黎明放黑猫、夜晚击杀/保护/自首）都能在界面上完成；超时由服务器自动处理。
3. 断网或切到后台再回来，画面自动恢复到当前状态。

## 2. 代码结构

新增 `client/`（TypeScript，结构与 `server/` 一致），用 esbuild 打包输出到 `minigame/game.js`。

```
client/
  src/
    core/     界面框架（不认识游戏规则）：场景切换、节点树、点击判断、补间动画、文字换行、重画调度
    theme/    月夜烛光主题：颜色、字号、背景 / 边框 / 卡牌 / 按钮 / 头像徽章的画法
    net/      云端：调用云函数、监听 rooms 和 hands、断线重连与轮询兜底、超时推进
    model/    纯逻辑（不依赖 wx，可单元测试）：
              · 由 rooms + hands 合成「画面数据」
              · 当前可做的操作、某张牌需要几个目标、哪些玩家可选
              · 事件日志 → 中文句子；卡牌 / 身份卡 / 死因的中文名与说明
    scenes/   首页、大厅、游戏桌、结算
    main.ts   入口
  test/       Vitest
  build.mjs   esbuild → ../minigame/game.js
```

- **单向数据流**：云端推送 → `net` 更新数据 → `model` 算出画面数据 → `scene` 重画。点击 → `model` 判断是否合法 → `net` 发请求。场景不保存游戏状态，一切以服务器推送为准。
- **与引擎共用代码**：客户端直接从 `engine/src` 引用类型（`PublicView`、`PrivateView`、`PendingChoice`、`GameEvent` 等）和常量（`targetCount`、`isRed` 等），由 esbuild 一并打包。卡牌中文名表放在 `client/src/model`（引擎里没有中文名）。
- **按需重画**：只有收到推送、发生点击或有动画进行中时才重画。
- **调试界面保留**：现有 `minigame/game.js` 移到 `tools/debug-harness/game.js`，需要时手动拷回使用。

## 3. 画面

### 3.1 首页
- 月夜背景、标题「女巫镇」。
- 按钮：**输入房号加入**（最显眼）、**创建房间**、**规则速查**。
- 规则速查：可滚动的面板，列出全部卡牌（按颜色分组）和身份卡说明；角色说明在计划 C 补充。
- 首次进入（本机没有昵称）先弹出昵称输入框（1–12 字）。首页右上角可修改昵称。
- 启动参数或回到前台参数里带 `room` 时，自动加入该房间（见 §7.1）。
- 本机记住上一次所在的房间：打开时若该房间仍在进行，提示「回到房间 1234？」。

### 3.2 大厅
- 大字显示房号，旁边「**复制房号**」。
- 座位列表：头像徽章、昵称、房主标记、机器人标记。
- 房主：每个座位「上移 / 下移」调整顺序；「加机器人」（每次 1 个，最多到 12 人）；「开始」（≥4 人才可点）。
- 所有人：「**邀请**」（发分享卡片）、「离开」。
- 房间状态变为 playing 时自动进入游戏桌。

### 3.3 游戏桌（自上而下）
1. **顶栏**：当前回合玩家、倒计时、牌堆数、弃牌数；夜晚时显示「夜晚」。
2. **玩家网格**（不含自己，最多 11 格，每行 4 格）：每格显示头像徽章、昵称、指控进度条（`redTotal / threshold`）、未翻开身份卡数、手牌数、蓝卡小图标（黑猫 / 情侣 / 避难 / 信徒）、拘留标记、死亡（整格变灰）。当前回合玩家的格子有金色发光边框。
   - 点格子弹出详情面板：角色、身份卡（已翻开的显示种类）、红卡明细、蓝卡、绿卡（拘留）。
3. **事件日志**：显示最近 3 条，点击展开全部（可滚动）。
4. **我的信息栏**：我的角色、指控进度、「我的身份卡」按钮（弹出面板显示自己 5 张身份卡；女巫阵营额外显示同伴名单；警长显示「你是警长」）。
5. **手牌区**：底部扇形排开，手牌多时压缩间距；下方操作按钮。

**轮到我时**：我的信息栏发光，顶部横幅「轮到你了」。
- `mode = choose`：按钮「抽 2 张」「出牌」（出牌 = 选中一张手牌后可用）。
- `mode = playing`（已出过牌）：按钮「继续出牌」「结束回合」。

**出牌流程**：点手牌 → 该牌抬起并放大显示效果文字 → 可选目标的格子（以及我自己的信息栏，若允许对自己出）亮起 → 依次点目标（嫁祸、抢劫要两个，按「第一个 → 第二个」提示）→「确认出牌」。再点一次已选中的牌或点空白处取消。
- 可选目标规则：必须活着；红卡不能对自己；信徒持有者不能被他人出红卡（与引擎一致，最终以服务器判定为准）。

### 3.4 选择面板（从底部弹出，带倒计时；超时由服务器随机代选）
| 待选择（`pending.kind`） | 面板内容 |
|---|---|
| `revealTryal`（`reason = trial`） | 「你被审判了」：从自己未翻开的身份卡中选一张翻开 |
| `revealTryal`（`reason = cat`） | 「传染：黑猫持有者翻一张身份卡」：同上 |
| `conspiracyPick` | 「传染：从左边玩家（昵称）的 N 张身份卡里盲选一张」：N 张背面朝上的卡 |
| `dawnVote` | 「第一夜：和同伴选择黑猫的主人」：玩家列表 + 同伴当前的选择 |
| `night` | 见 3.5 |

提交后面板显示「等待其他玩家…」，直到阶段变化。

### 3.5 夜晚
- 进入夜晚时全屏渐暗、月亮升起。**所有人的面板结构相同**（防止旁人看屏幕猜身份）：
  1. 第一步「选择一名玩家」：女巫阵营 = 击杀目标（显示同伴的选择，须一致）；警长 = 保护对象（不能选自己）；其他人 = 怀疑对象（纯装饰，只在本地记录，不发请求）。
  2. 第二步「是否自首」：选择一张自己的身份卡翻开，或「不自首」。
- 自首一旦提交不能撤回。第一步在夜晚结束前可以改选（重新发 `witchVote` / `protect`）。

### 3.6 结算页
- 大字「村民胜利」或「女巫胜利」。
- 所有人的身份卡全部翻开，列出每个人的阵营、存活状态。
- 按钮「回到首页」。

### 3.7 动效（每个约 0.3 秒，不阻塞操作）
抽牌时牌从牌堆滑入手牌；出牌时牌飞向目标格子；当前回合格子金色呼吸光；夜晚渐暗 / 天亮渐亮；死亡时格子渐变为灰；翻身份卡时做翻转；选择面板从底部滑出。

## 4. 联网

- **进入房间**：先 `get` 一次 `rooms/{code}` 和我的 `hands`，再建立 `watch`。
- **只认当前这一局的手牌**：`hands.gameId` 与 `rooms.gameId` 不同则忽略（房号复用时的旧手牌）。
- **我是谁**：`createRoom` / `joinRoom` 返回的 `openid`，用来在座位中找到自己、判断是否房主。
- **断线重连**：watch 出错后按 1s、2s、4s… 最多 30s 退避重连；连续失败 3 次后改为每 3 秒 `get` 一次 `rooms` 和 `hands`，同时后台继续尝试恢复 watch。`wx.onShow` 时立即重新拉取一次。
- **发送操作**：每次 `act` 都带 `version`。返回「状态已变化，请重试」时不提示，等下一次推送；其他错误用顶部提示条显示 2 秒。请求进行中按钮显示「处理中」并禁止重复点击。
- **超时推进**：倒计时到 0 后，再随机等待 0–1.5 秒调用 `tick`；同一时间最多一个 `tick` 请求；`tick` 的错误一律忽略。
- **倒计时**：用 `rooms.deadline − 本机时间` 显示，不做时钟校准（服务器会再次核对是否真的超时）。

## 5. 出错与边界情况

- 云函数调用失败（网络问题）：提示「网络不稳定，正在重试」，保持当前画面，等推送或轮询恢复。
- 房间不存在 / 已结束：回首页并提示。
- 我不在座位中（例如被当作离开）：回首页并提示。
- 游戏中途重新打开小游戏：通过「上一次所在的房间」回到游戏桌，画面由重新拉取的数据恢复。
- 已死亡：界面照常显示，但没有操作按钮，信息栏显示「你已出局」。

## 6. 测试

- **Vitest**（不依赖 wx）：
  - `model`：rooms + hands → 画面数据；各阶段可做的操作；每张牌的目标数量与可选目标；日志翻译；gameId 过滤。
  - `core`：点击判断、布局计算、文字换行（注入假的文字宽度测量函数）、补间动画插值。
  - `net`：用假的 `wx` 对象测试重连退避、轮询兜底、`tick` 节流、`act` 带版本号和错误处理。
- **构建检查**：`tsc --noEmit`、esbuild 打包成功。
- **真机测试**：开发者工具模拟器 + 体验版在 2–3 台手机上实际打一局（可加机器人凑人数）。

## 7. 风险与已验证事项

### 7.1 分享卡片（2026-09-28 已试验）
- 已确认：`wx.showShareMenu` 后「转发」可用；体验版卡片能从群聊打开小游戏（scene 1008）；启动参数可读取。
- 未解决：`wx.onShareAppMessage` 在模拟器中生效（自定义标题、`query: room=…`），但**在手机上（体验版 0.1.1）分享时回调根本没有被调用**（回调内的日志没有出现），卡片是默认标题、不带 query，原因未查明。
- 因此采用「复制房号 + 首页输入房号」为主要入口；读取 `room` 参数自动加入的代码保留，若日后手机上生效则自动可用。

### 7.2 其他
- Canvas 中文字体：只用系统默认字体（不加载字体文件），通过字号、字重、颜色和描边体现风格。
- 性能：12 人局同屏元素约数百个，按需重画即可；若低端机卡顿，再做分层缓存（背景画到离屏画布）。
